## 6. Code smells: the five that fail most

### S1. WUI e2e geometry asserts run against whatever font the runner has (27 failed e2e jobs, 0 of them collateral)

- Asserts to the pixel: `csi-spl-wui/tests/e2e/phone-composer-target.test.mjs:318`
  (`s.textEnd >= s.slot - 1`), `:230-231` (text end and the Search slot read
  from `getBoundingClientRect`); the same shape in `issues-crud-modal` (K4)
  and `issues-bulk-shift` (check 4); `boxes-three-panes.test.mjs:204` per
  6d2bb929f's message.
- Nothing pins the font: `git grep -nE 'FONTCONFIG|fonts-noto|fonts-dejavu' -- .github/workflows`
  -> 0 lines. Two tests already document the split:
  `csi-spl-wui/tests/e2e/card-edge-inset.test.mjs:20` ("Noto Sans on one CI
  box and DejaVu Sans on another"), `move-by-drag.test.mjs:426`.
- Why it fails often: a lane proves its layout on the box (Noto); the gate
  runs on the hosted runner (DejaVu); a 1 to 3 px difference flips a strict
  assert (2 of the 7 WUI defects, by their fix messages). The other WUI reds
  are real regressions that the lane's chosen e2e files did not cover.

### S2. Orc test fixtures borrow host binaries and shell behaviour (16 jobs, family C)

- The fixed pattern was a copy of `sleep` renamed to the process a test
  fakes. Copies are gone (`git grep -nE 'cp[^|;]*(command -v sleep|/bin/sleep|which sleep)' origin/master -- '*.sh'`
  -> 0), but two **symlinks** to `sleep` under another name remain:
  `csi-spl-orc/src/bash/features/spawn-agents/tests/test-spool-send.sh:69`
  (`ln -s "$(command -v sleep)" "$T_TMP/sudo"`) and
  `csi-spl-orc/src/bash/features/spawn-agents/tests/test-tmux-close-window.sh:352`
  (`claude`, `grok`, `agy`). On a multi-call coreutils a symlink dispatches on
  its name the same way a copy does. Whether these two cases still prove what
  they claim on 26.04: unchecked (the orc feature job was green on 26.04 at
  16:47Z, n=1, which may only mean the fake is never run long).
- Host versions the suite depends on: bash 5.2 vs 5.3, OpenSSH 10.0 vs 10.2.
  Nothing runs the orc suite on the next image before `ubuntu-latest` moves.

### S3. The deploy watcher reads a canary split as "unhealthy" (22 jobs, family E)

- `csi-spl-orc/src/bash/run/check-hub-deploy.func.sh:93-96`: any serving
  split other than `<latest>:100` returns 4, "unhealthy". The hub rolls
  through a canary on dev and prd (`csi-spl-cnf/csi-spl/prd.env.yaml` and
  `dev.env.yaml`: `canary:` enabled, SPL-2249; defaults `percent: 10`,
  `minutes: 10` at `csi-spl-cnf/csi-spl/all.env.yaml:410-413`). An hourly
  tick that lands inside a split goes red.
- Cost: 9 red hourly runs of 118 (8%), each a red badge on the repo page.

### S4. Tests that read live repo config or a moving default (7 B jobs + 2 D jobs)

- `csi-spl-orc/src/bash/tests/tenant-host.tst.sh:56` copies the live
  `csi-spl-cnf/csi-spl/dev.env.yaml` into the fixture and pins only
  `mapped_tenants`; the steps.052 workspace list still comes from the live
  file, so a cnf edit (892b03122, SPL-2947) turned an orc test red (4 jobs).
- `csi-spl-orc/src/bash/tests/dispatch-setup-check.tst.sh:341` case 7 relied
  on the action's default grace; the default moved 30 -> 60 (178dc2b4f) and
  the test was red until it pinned `DISPATCH_LAG_GRACE=30` (c6ee3f5d3).
- `csi-spl-iac/src/bash/tests/check-pre-push-baseline.tst.sh` case 9e counted
  Go cache files (want 10, got 12): it measured the runner's Go, not the gate.

### S5. A Go test pins WUI source text (5 jobs), and store groups share rows (1 job)

- `csi-spl-api/src/go/spool-hub-api/internal/store/flow_mentions_test.go:72-86`
  reads `csi-spl-wui/src/utils/{agent-id,notify,mention-poke}.mjs` as text and

  them (e86f7b9b1) broke the hub job; the WUI lane and its reviewer did not

- `TestPutFXRates` failed on rows an earlier store group wrote (8993bf9ed):
  the Postgres groups share one database.
