## How to work

- One commit per site. Each commit message carries the before/after numbers, n, the method and the trunk sha.
- Add a test that pins the gain where the method allows (an RT budget, a bench committed beside the file, a listener/element count, a golden or byte-compare test against the old behaviour). Prove the test by planting the old behaviour once (a control that fails).
- Live DB / hub rows: after the roll on dev AND prd, read the same read-only action as "now" over the same window length and report it. Live reads use the per-environment service-account key only (`~/.gcp/.csi/key-csi-spl-<env>.json`, a throwaway `CLOUDSDK_CONFIG`, `--account` on every call), never the owner account, and never mutate.
