# Performance Round 5: Proposal a1 (agy)

## 1. 30+ Best Practices for Performance and Design

### Architectural & System Patterns
1. **App Shell Architecture**: Warm service-worker caching for UI.
2. **Read-Through / Write-Through Caching**: Cache edge responses and invalidate appropriately.
3. **Pipelining / Batching RPCs**: Group independent queries into single network round-trips.
4. **Denormalized Counters / Head Rows**: Maintain totals asynchronously or via triggers rather than computing on read.
5. **Event-Sourced Tails**: Compute state only from recent events since a known checkpoint (e.g., read marks).
6. **Parallel Map-Reduce**: Split large loops into concurrent executions.
7. **Single Connection multiplexing**: Route multiple streams through one WS connection.

### Database Patterns
8. **CTE (Common Table Expressions) for Lock-Free Updates**: Update and returning data in one query to avoid race conditions and round trips.
9. **Index-Only Scans**: Utilize covering indexes to prevent heap fetches.
10. **Autovacuum Tuning**: Aggressively vacuum append-only or high-churn tables (scale factors).
11. **Filter Early**: Use precise index filters (e.g., no OR conditions) before joining large datasets.
12. **Materialized Views / Partial Indexes**: Pre-compute results for hot queries.
13. **Batch Writes**: Group INSERTS/UPDATES in `pgx.Batch`.
14. **Avoid N+1 Queries**: Fetch related entities in one join instead of loops.
15. **RETURNING clauses**: Fetch updated state in the same round-trip.

### Go / Backend Speed
16. **Structs over Maps**: Use statically typed structs over `map[string]any` to reduce allocations.
17. **Buffer Pooling (`sync.Pool`)**: Reuse memory buffers for JSON serialization.
18. **Write-Once Fan-Out**: Encode a broadcast message once, copy raw bytes to N sockets.
19. **Memoization in Request Scope**: Cache redundant DB lookups inside a single HTTP context.
20. **Zero-Allocation Parsing**: Avoid `[]byte` to `string` copies where possible.
21. **Deferred Initialization**: Setup expensive regexes or objects once globally.
22. **Avoid double-marshaling**: Canonicalize JSON objects without map interfaces.

### Frontend / WUI Speed
23. **Passive rAF Viewport Listeners**: Consolidate window resizing/scrolling into single Animation Frame callbacks.
24. **Avoid Forced Synchronous Layouts**: Measure DOM off-screen or via ResizeObserver.
25. **Measure Text via Canvas**: Avoid DOM insertion to measure text width.
26. **Intl Object Re-use**: Instantiate `Intl.Collator` or `Intl.NumberFormat` once globally.
27. **Lazy chunk loading**: Defer heavy components (e.g., language switchers) until needed.
28. **Disable ICU collation on machine keys**: Use `localeCompare` only for human text.
29. **v-if over v-show**: Unmount hidden DOM nodes to reduce VDOM size.
30. **Debounce / Throttle Synchronizations**: Don't loop heavy queries on rapid user input.

## 3. Not Worth Doing, and Why

Based on empirical evidence from past rounds and prd route timings:
- **Index-only message join for Flow counts**: Tried in API perf round (ea9dc09a) and failed because some `flow_events` have different timestamps than `messages`, causing data loss (md5 mismatch). Not worth doing due to correctness risk.
- **OR conditions split in DM walk (`view_topics`)**: Caused the planner to use a Bitmap Heap Scan taking 5-7 seconds (vs 114-286ms). Hub disables bitmap scans, so this rewrite is dangerous without specific planner configurations.
- **Memoizing repeated queries across requests**: Cache invalidation (e.g., channel counts) is too rapid due to constant `read_marks` bumps, defeating the cache hit rate.
- **Micro-optimizing `INSERT INTO boxes`**: Costs 0.63ms per call (44.2s total over 24h) but is asynchronous and blocking no user screens. No measurable gain for real UX.
- **Cache CDN Edge for authenticated /v1/view/flow**: Response is private, so it cannot be cached globally.

## 4. The 10 Most Beneficial Actions (Concrete Proposals)

### 1. Fix browser channel re-read loop on empty ID marks
- **Practice**: #30 (Debounce/Throttle)
- **File:Line**: `csi-spl-wui/src/utils/read-sync.mjs` (mergeMarks / laterThan)
- **What is wrong NOW**: WUI re-reads the channel list every 5s per open channel because of an empty message ID tie. Prd 8.4h: 4,670 channel GETs vs 4,817 PUTs, causing 26.3% of DB time.
- **Change**: Fix the echo so an empty local ID does not trigger a newer-mark reload.
- **Expected Gain**: Drop 600s/day of DB load; Flow-count wakes behind them vanish.
- **Proof**: Dev browser network log (n>=20 PUTs on open channel); prd 24h GET count drops.
- **Evidence (For/Against)**: **For**: Identified in round ea9dc09a as 25%+ of DB load. **Against**: Risk of cross-device mark missing if not careful, but easily tested.

### 2. Event-Sourced Flow Badge Counts (Schema)
- **Practice**: #5 (Event-Sourced Tails)
- **File:Line**: `csi-spl-rdb/src/sql/postgres/spool-hub/0136_flow_events_place_key.sql` and `csi-spl-api/src/go/spool-hub-api/internal/store/flow_postgres.go:26-50`
- **What is wrong NOW**: Flow counts scan the entire `messages` table and `read_marks` once per event a member ever got (O(all events)). 37.8% of prd DB time.
- **Change**: Add `place_key` and `cov_at` to `flow_events` and index them. Maintain with an AFTER UPDATE trigger on messages.
- **Expected Gain**: Enables O(unread) flow counting.
- **Proof**: Backfill row count matches flow_events; 0 mismatches on read.
- **Evidence (For/Against)**: **For**: Essential enabler for the massive DB win. **Against**: Increases write cost by 1 index entry per event.

### 3. Event-Sourced Flow Badge Counts (Read)

### 5. Tune messages table autovacuum for Index-Only Scans

### 7. Denormalize Topic Head Row
- **Practice**: #4 (Denormalized Counters / Head Rows)
