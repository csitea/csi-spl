## 1. 30+ Best Practices for Performance and Design

<a id="ws-doc-debdd06a-e1ea-4fdc-a20f-4db68239d3f5"></a>
### Architectural & System Patterns
1. **App Shell Architecture**: Warm service-worker caching for UI.
2. **Read-Through / Write-Through Caching**: Cache edge responses and invalidate appropriately.
3. **Pipelining / Batching RPCs**: Group independent queries into single network round-trips.
4. **Denormalized Counters / Head Rows**: Maintain totals asynchronously or via triggers rather than computing on read.
5. **Event-Sourced Tails**: Compute state only from recent events since a known checkpoint (e.g., read marks).
6. **Parallel Map-Reduce**: Split large loops into concurrent executions.
7. **Single Connection multiplexing**: Route multiple streams through one WS connection.

<a id="ws-doc-e7c3afcf-d551-4d4e-85fb-8c00529f6e88"></a>
### Database Patterns
8. **CTE (Common Table Expressions) for Lock-Free Updates**: Update and returning data in one query to avoid race conditions and round trips.
9. **Index-Only Scans**: Utilize covering indexes to prevent heap fetches.
10. **Autovacuum Tuning**: Aggressively vacuum append-only or high-churn tables (scale factors).
11. **Filter Early**: Use precise index filters (e.g., no OR conditions) before joining large datasets.
12. **Materialized Views / Partial Indexes**: Pre-compute results for hot queries.
13. **Batch Writes**: Group INSERTS/UPDATES in `pgx.Batch`.
14. **Avoid N+1 Queries**: Fetch related entities in one join instead of loops.
15. **RETURNING clauses**: Fetch updated state in the same round-trip.

<a id="ws-doc-1670dfd4-dd91-404b-89e7-9453d3710c0e"></a>
### Go / Backend Speed
16. **Structs over Maps**: Use statically typed structs over `map[string]any` to reduce allocations.
17. **Buffer Pooling (`sync.Pool`)**: Reuse memory buffers for JSON serialization.
18. **Write-Once Fan-Out**: Encode a broadcast message once, copy raw bytes to N sockets.
19. **Memoization in Request Scope**: Cache redundant DB lookups inside a single HTTP context.
20. **Zero-Allocation Parsing**: Avoid `[]byte` to `string` copies where possible.
21. **Deferred Initialization**: Setup expensive regexes or objects once globally.
22. **Avoid double-marshaling**: Canonicalize JSON objects without map interfaces.

<a id="ws-doc-a0f94a78-594b-4b2b-b609-1c35fc3c5dc2"></a>
### Frontend / WUI Speed
23. **Passive rAF Viewport Listeners**: Consolidate window resizing/scrolling into single Animation Frame callbacks.
24. **Avoid Forced Synchronous Layouts**: Measure DOM off-screen or via ResizeObserver.
25. **Measure Text via Canvas**: Avoid DOM insertion to measure text width.
26. **Intl Object Re-use**: Instantiate `Intl.Collator` or `Intl.NumberFormat` once globally.
27. **Lazy chunk loading**: Defer heavy components (e.g., language switchers) until needed.
28. **Disable ICU collation on machine keys**: Use `localeCompare` only for human text.
29. **v-if over v-show**: Unmount hidden DOM nodes to reduce VDOM size.
30. **Debounce / Throttle Synchronizations**: Don't loop heavy queries on rapid user input.

### 1. Debounce Flow Count DB probes on WUI wakes
- **Practice**: #30 (Debounce/Throttle)
- **File:Line**: `csi-spl-api/src/go/spool-hub-api/internal/hub/wui_wake.go:61`
- **What is wrong NOW**: `s.pushFlowCounts` is called immediately for every read-mark wake. Measurement: `(FlowCounts)` query runs 5,882 times per 24h, consuming 24.1s (6.9% of DB time).
- **Change**: Coalesce wakes for a member within a ~500ms window before probing the DB.
- **Expected Gain**: >50% reduction in `FlowCounts` DB calls during rapid marking.
- **Evidence**: **For**: 24s of DB time spent heavily on rapid successive read marks. **Against**: Delays badge updates by the window duration.

### 2. Optimize Message Insert parsing (`to_tsvector`)
- **Practice**: #21 (Deferred Initialization)
- **File:Line**: `csi-spl-rdb/src/sql/postgres/spool-hub/0135_messages_search_sig.sql:58`
- **What is wrong NOW**: Insert takes 62.15 ms x 298 calls. The trigger double-parses `NEW.body` using `to_tsvector` even though Postgres automatically computes the generated `search_tsv` column.
- **Change**: Update the trigger to use `spool_search_sig(NEW.search_tsv)`.
- **Expected Gain**: Drops redundant CPU parsing cost on bodies >1024 chars.
- **Evidence**: **For**: 62ms per insert is very slow; thousands of live messages are long enough to trigger the double parse. **Against**: Requires validating `search_tsv` is populated before the AFTER trigger runs.

### 3. Replace OR condition in Topic Archive filter
- **Practice**: #11 (Filter Early)
- **File:Line**: `csi-spl-api/src/go/spool-hub-api/internal/store/topic_archive_postgres.go:363` (`archivedTopicHideSQL`)
- **What is wrong NOW**: The `OR` condition `(z.msg_id = a.task_id OR z.task_id = a.task_id)` forces a bitmap heap scan.

### 4. Fetch Walk Subject via Covering Index
- **Practice**: #9 (Index-Only Scans)
- **File:Line**: `csi-spl-api/src/go/spool-hub-api/internal/store/view_postgres.go:351` (`summary`)
- **What is wrong NOW**: `LEFT JOIN LATERAL` onto the `messages` table reads the heap to find the first message line for `f.first_msg`. Walk DM averages 82.16ms per call.
- **Change**: Modify `subjectSQL` to read directly from the `messages_task_received` index using `LIMIT 1`.
- **Expected Gain**: ~20-30ms reduction per walk.
- **Evidence**: **For**: The `CROSS JOIN` heap access scales linearly with topic count. **Against**: May require adding `body` to an index or maintaining a short denormalized title.

### 7. Avoid Recomputing Flow Counts on Fanout
- **Practice**: #5 (Event-Sourced Tails)
- **File:Line**: `csi-spl-api/src/go/spool-hub-api/internal/store/flow_postgres.go:180` (`FlowFanout`)
- **What is wrong NOW**: `FlowFanout` averages 21.31 ms x 310 calls. It uses a `CROSS JOIN LATERAL flowCountsSQL` to recompute the entire Flow badge for every recipient.
- **Change**: WUI already caches counts; hub should just push the +1 event delta, skipping full `flowCountsSQL`.
- **Expected Gain**: Eliminates the 21ms `FlowFanout` DB query completely.
- **Evidence**: **For**: The WUI has a reactive store that can handle deltas. **Against**: Delta math can drift if the WUI misses a WebSocket frame (though read-sync corrects it eventually).

### 8. Remove `fileRefs` JSON unmarshal in Search
- **Practice**: #4 (Denormalized Counters)
- **File:Line**: `csi-spl-api/src/go/spool-hub-api/internal/store/search.go:125` (`searchMsg`)
- **What is wrong NOW**: `len(fileRefs(m.Files))` parses raw JSON just to count files during the expensive search route (320.10 ms x 6 calls).
