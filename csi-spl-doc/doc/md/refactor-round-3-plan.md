## 1. How to read this

- One row = one practice = one lane, which applies it at the sites named and nowhere else. Each row also does the docs, comment and testability items its brief names, in the same files.
- **Concurrency (owner msg a4930378):** up to 8 row lanes per box, 16 at once, at least 2 grok lanes per box. Batch 1 = rows 1-16 (8 on `sat`, 8 on `PC`); batch 2 = rows 17-30.
- **Boxes:** `sat` = the satellite; `PC` = the owner's primary box (its short name is banned in shipped files by the hygiene sweep; the lane map prints it). WUI and browser rows run on `PC` because `sat` is loaded; Go rows that touch `internal/store` run on `PC` too (they need Postgres, which `sat` lacks).
- **File-disjoint:** no file appears in two rows, with one exception: rows 13 and 28 share `csi-spl-iac/src/bash/run/tf-destroy-local-step-bucket.func.sh`. Both run on `sat`, marked `same-box serial`: 13 first (batch 1), 28 after it lands (batch 2).

- **New ground:** no file named by refactor rounds 1 and 2, perf round 4, the 20261004 perf edition (plan and briefs) or the 20261004 availability plan is used (basename check). No practice repeats a round-1 or round-2 practice name, except row 18 (`slices.Sort`), whose 5 sites are new plain-sort sites (88 in the tree; round 2 did only `sort.SliceStable`).
- **Kept off:** migrations, `internal/msg/msg.go`, `internal/store/fleet_*.go`, the rotation / lease / spawn / dispatch scripts. Row 5's `internal/store/migrate.go` is the Go migrate runner, not a migration.
- **Off every live lane:** `lane-map.sh --check <all 167 paths> --agent c-274` printed `free`, rc 0 (2026-10-05T04:52Z, trunk `755e86235`).
- **Behaviour-preserving, no new dependency.** Rows 6, 7, 11 and 15 change only the failure path (a hang becomes a bounded failure; a failed container setup ends the container), which is the stability the owner asked for. Every other row is the same behaviour.
- **Split:** 8 Go, 12 TS/Vue, 10 bash, by the size of each tree on `755e86235` (735 Go, 1081 Vue/TS/mjs, 941 bash files). 16 stability rows first, then 14 clean-code rows.
- **Agent:** `grok` for the mechanical, low-risk rows (12 rows: 4 per box in batch 1, the rest in batch 2); `claude` for the rest, and for every row that touches credential paths (12, 13).
