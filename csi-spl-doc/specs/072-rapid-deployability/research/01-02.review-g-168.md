## 2. Blockers

1. **Cold lde cannot build the hub.** `build.sh:6` forces `GOPROXY=off`
   and `GOTOOLCHAIN=local`. `go.mod:5` is `go 1.25.14`. The failure text
   is `FATAL static spool build failed` (`setup-app-inf.func.sh:89`),
   which does not name `go mod download`. A warm cache hides it: 37 s, 5/5.
2. **lde requires the agent spool group.** `setup-app-inf.func.sh:47`
   calls `do_provision_spool_root`. Missing group and missing directory
   -> fatal (`provision-spool-root.func.sh:28-35`). Reproduced in a
   container, n = 1. The repair action defaults to a dry run.
3. **The WUI README's hub check 404s.** `csi-spl-wui/README.md:155` and
   `:271` still say `/v1/view/threads`. Measured 404. `view.go:49` is
   `/v1/view/topics`.
4. **A human cannot post on the default lde stack.** Both runs logged
   `auth_native=0`. Sign-in is off unless `LDE_AUTH_NATIVE=1` is passed
   to **both** commands (`csi-spl-wui/README.md:170-174`). Spec 072
   section 2 measure 1 is a human and an agent posting. `GET /` 200 is
   not that.
5. **The first error's apt line is the wrong shopping list.** It names
   `docker.io`, `curl` and `yq`, and not the compose plugin, a Go 1.25
   toolchain, or `setfacl` (`require-bin.func.sh:26,35`).
6. **The project id ignores the outsider's org.** Directory name wins.
   Measured: a placeholder org still planned `csi-spl-dev`. Nine
   `regex("^csi-spl` validations (`grep -rnF | wc -l` -> 9). Fourteen
   files lock `contains(["dev", "prd"]`.
7. **An empty `GCP_ORG_ID` does not clear the cnf.** Measured equal to
   unset. gcp-000 then requires that value (`gcp-000:21-22`) and gcp-001
   rejects org plus folder (`gcp-001:51`). A folder-only outsider who
   exports an empty org id still hits our org id from
   `all.env.yaml:27`.
8. **Dry run is not a plan.** It mints a token first (`gcp-001:81`).
   gcp-003 then fatals if the SA is absent (`gcp-003:45-46`), so 003 and
   004 never print on a fresh project.
9. **A second shell after the key exists is not the human.** The key
   file beats the owner login (`gcp-account-pin.func.sh:180-183`).
   gcp-002 writes that file before gcp-003 grants `roles/owner`.
   Re-running gcp-000 authenticates as the SA that cannot grant itself.
10. **The cnf README denies what the file holds.**
    `csi-spl-cnf/README.md:8` says org id and operator identity are not
    in cnf. `all.env.yaml:26-27` are `gcp_account_owner_email` and
    `gcp_org_id`, both non-empty (email, numeric). An outsider who
    trusts the README does not know the default target.
11. **gcp-002 can change the whole org and not put it back.**
    `user:$GCP_ACCOUNT` receives `roles/orgpolicy.policyAdmin` at the
    org (`gcp-002:128-130`) and nothing removes it. The org policy
    document is replaced with a one-rule body (`:119-123`), then set
    back to enforce, not to the previous document. The wait is up to
    10+30+60+120 s (`:153`).

## 3. Actions

Effort: XS < 0.5 day, S <= 1 day. One lane each.

1. **Build lde without a host module cache** (01's A1). `do_setup_app_inf`
   builds from `csi-spl-api/src/docker/hub.Dockerfile` (multi-stage,
   `golang:1.25-alpine`, line 12). The lde Dockerfile today only copies
   a host binary. Done when `env -i HOME=$(mktemp -d)` and an empty
   `GOMODCACHE` still get 5/5 PASS. S.
2. **Drop `do_provision_spool_root` from `do_setup_app_inf`** (01's A2),
   behind `LDE_SPOOL_ROOT=1` for the harness. Done when
   `SPOOL_ROOT_GROUP=no-such-group` and a missing `SPOOL_ROOT_DIR` exit 0
   and do not create `/var/spool-hub`. XS. The fatal is already reproduced.
3. **Point the WUI README at routes that answer.** Replace
   `/v1/view/threads` with `/v1/view/topics`. Done when
   `grep -c view/threads csi-spl-wui/README.md` -> 0 and a curl of every
   remaining `/v1/view/` URL in that file returns 200 on lde. XS.
4. **`do_lde_up`** (01's A6) runs setup, then wui install, and prints the
   hub URL, the WUI URL, and whether sign-in is off. `LDE_AUTH_NATIVE=1`
   is passed to both steps. Done when one command on a fresh clone
   reaches `healthz` 200 and `GET /` 200, and with the switch set a
   register call returns a debug token. S.
5. **Project id from cnf, and an explicit org** (02's G1, plus blocker 7).
   `do_gcp_spl_proj_id` uses `env.gcp.gcp_project` when it is a legal id.
   `GCP_ORG_ID=` means "not the cnf value". gcp-000 sets the org from
   cnf only when the variable is unset **and** `GCP_FOLDER_ID` is empty.
   Done when a fixture under `csi-spl-iac` plans `projects create` of
   the fixture's id, and `GCP_ORG_ID= GCP_FOLDER_ID=123` plans
   `--folder=123` with no "not both". S.
6. **The human stays the identity until 003 has succeeded.** A stamp
   next to the key, written only by gcp-003. Until the stamp exists,
   bootstrap mode does not pick the key. Done when a stub with a key
   file and no stamp still logs the owner-login path, and with a stamp
   logs the SA. S.
7. **A dry run prints all four steps** (02's G3). gcp-003 and gcp-004
   take `BOOTSTRAP_PLANNED=1` and do not fatal on a missing SA. A
   describe that says "it may not exist" is **taken**, not absent
   (`gcp-001:94` is that pattern). Done when a NOT_FOUND stub prints
   four `OK DRY_RUN` lines and exits 0, and an "it may not exist" stub
   exits non-zero naming the id. S.

**Line numbers the lead should not copy.** gcp-002:128-130 (the

| their citation | this tree (`wc -l`) |

**Resume is not safe after the key exists.** Their B10 says a half-built
estate can be resumed because every step is safe to re-run. That is
true inside one shell, where `GCP_ACCOUNT` stays exported. A new shell
resolves the key file first (`gcp-account-pin.func.sh:180-183`) and
never reaches the owner login. gcp-003 has not granted `roles/owner`
yet, so the SA cannot finish the grant. Action 6 is the fix. Their
G5 (keyless) also removes this trap; it does not make today's resume
true.

**Rank.** Their top 3 leads with G5, keyless bootstrap. I would ship
action 5 first. An outsider whose project id is `csi-spl-dev` (measured,
even with a foreign org id) never reaches the org-policy step. G5 is
the right default once a project can be created. It is not the first
hour of DevEx.
