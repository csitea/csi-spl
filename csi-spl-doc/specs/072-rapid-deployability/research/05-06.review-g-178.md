## 2. Blockers

1. **The odometer dies at `9.9.9`.** `spl_version_valid` is `^[0-9]\.[0-9]\.[0-9]$` (`spl-release-version.func.sh:25`). The mint logs FATAL at line 192. Workflows 20 and 30 accept only the same one-digit shape (`grep -xE '[0-9]\.[0-9]\.[0-9]'`). 159 successful mints remain. Both deploys stop together, because they share the tag.
2. **A fork cannot name its project, registry or site.** Three refusals, three files: `spl-cloud-cnf.func.sh:111` (FATAL), 028 `:37`, 019 `:42`. GCP project ids and Firebase Hosting site ids are global, so our two ids are already taken and the regex then rejects every other id. Passing 019 is a one-line edit of our validation; the global uniqueness of the id we already created is Firebase's, and it is a separate fact (019's own comment at `03-firebase-site.tf`).
3. **A missing secret is a green run.** Both workflows skip the env with `::notice::` (wf 20:164, wf 30:146). The workflow spells `GCP_KEY_CSI_SPL_<ENV>` (12 and 8 hits). Step 120 writes `GCP_KEY_<ORG>_<APP>_<ENV>`. After a rename, every env is skipped and the check mark stays green.
4. **The comments describe a deploy this tree no longer does.** Still teaching "bump `hub.image.tag`, plan, apply": `dev.env.yaml:178`, `prd.env.yaml:185`, `030-cloud-run-hub/02-variables.tf:44`, `build-push-hub-image.func.sh:74`. Still teaching a 031 load balancer: wf 20:635-636 (allowlist, ingress `internal-and-cloud-load-balancing`), wf 30:7-13, `render-wui-firebase-json.sh:42-44`, `019/.../02-variables.tf:47-56` (product hosts "are NOT Firebase custom domains"). Measured: no 031 directory, ingress `all`, `bind_custom_domain: true` in both envs.
5. **A green WUI deploy does not prove the host a person opens.** The probe adds `<fqdn>` only when `wui_origin_host` is set (wf 30:444-448). That key is absent from every env yaml, so the probe is only `https://<site>.web.app/build.json`. The host in DNS is the Firebase custom domain.
6. **No named deploy action for either half.** The roll is an inline `gcloud` in workflow 20 (`grep -c 'run services update'` -> 1, that file only). The WUI has no `do_deploy_static_site`. Repo rule: a step a person would type once becomes an action. A box without GitHub Actions has to copy the workflow.
7. **`nuxt generate` with no API base ships localhost.** `nuxt.config.ts:55`. `NUXT_PUBLIC_USE_MOCK` defaults to `"0"` outside `nuxt dev` (`nuxt.config.ts:49`). A contributor who runs the script the way `package.json` documents publishes a bundle aimed at `{tenant}.localhost`.
8. **Two proxies.** CI migrates with cloud-sql-proxy `v2.14.1` (wf 20:604, downloaded when missing). Operators follow cnf `cloud_sql_proxy_image` `2.18.0` (`all.env.yaml:235`). The same step installs `yq` from `releases/latest` (wf 20:599).
9. **Cloud build needs a host Go and a warm module cache.** `build.sh:6` sets `GOPROXY=off`. `do_build_push_hub_image` does not run `go mod download`. Compose builds inside Docker and does not ask for this. A P2 deploy from a laptop fails until someone knows both facts.

## 5. Where I disagree

I re-counted the odometer on `ae839a3d0` and got the same six full days (106, 55, 118, 154, 154, 130) and the same 159 steps. That part of the landed 05 note stands, including the urgency.

1. **Names before a unified image.** The landed 05 note ranks one Dockerfile (its H2) and a new deploy action (its H3) ahead of dropping the project-id FATAL and the registry regex (its H4). A fork stops at `spl-cloud-cnf.func.sh:111` and at 028 `:37`, which is before any image builds. R2 and R3 are the second and third changes. Two Dockerfiles stay a real gap (compose's entrypoint seats an owner and refuses a default password; Cloud Run's image is distroless and has no shell), and closing it is the lane after a fork can push the image it already has.

2. **The always-on hub is the cost that belongs in section 05.** The landed 05 note prices runners and registry storage and leaves the service out. Section 1.4 is the missing row: about $50 per env per month, about $100 for the pair, from `min_instances: 1` and `cpu_idle = false`. It changes measure 1, which is why Q3 is asked. It does not outrank R1.

3. **The stale text is the load balancer, not only "plan and apply".** The landed 05 note's section 1.4 lists the bump-and-apply lines. It does not list wf 20:635-636, wf 30:7-13, the renderer at lines 42-44, or 019 `02-variables.tf:47-56`. Those four still describe step 031. `ls` finds no 031 directory. An outsider who follows them provisions a load balancer this tree removed in 2026-09, and then cannot match ingress `all`.

4. **The product host is not what workflow 30 probes.** The landed 06 note records the check as `<site>.web.app/build.json` and ranks the certificate-wait copy (its W7) as the long pole of the custom domain. `wui_origin_host` is 0 across the env yaml files, and `bind_custom_domain: true` is set in both live envs, so the host a person types is a Firebase custom domain that this probe never fetches. R5 is smaller than W7 and it checks the thing the user opens. The certificate wait remains real; it is not the first gap.

5. **A runtime `config.json` is the end state, and it is not the first WUI edit.** The landed 06 note's top action is that file (its W1, effort M), so one bundle serves any domain. I agree with the end state and with widening it to compose and Hosting together. The first edits are the site-id regex and the silent skip (its own W2 and W4, which match R2 and R3 here), then the fail-closed generate (R6). `nuxt.config.ts:55` will publish localhost today, which W1 does not have to wait on. A config request that 404s is a blank app; a generate that exits names the variable.

6. **The registry escape does not need an unchecked platform claim.** The landed 05 note's H6 says, as an unchecked belief, that Cloud Run cannot pull a public registry directly, and so asks for an Artifact Registry remote repository (effort M). I did not verify that claim either, so this note does not design around it. The step a test can check is an explicit `hub.image.ref` in cnf, with today's derivation kept as the default when the key is empty.

7. **Pin the proxy the migrate step actually runs.** The landed 05 note's H8 pins `yq`. The same step's cloud-sql-proxy is `v2.14.1` while cnf says `2.18.0`. R8 pins both, to the cnf tag for the proxy. CI and an operator otherwise migrate through different builds of the same tool.
