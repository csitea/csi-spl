### 1.2 DNS, TLS, tenant hosts

One domain literal, cnf key `env.dns.BASE_DOMAIN`, `all.env.yaml:12`. `fqdn` is `<env_subdomain>.<BASE_DOMAIN>`, or the apex when the subdomain is empty (`all.env.yaml:9-10`).

P1 names: Caddy is the only front door. `SPOOL_SITE_ADDRESS` default `:80` is plain HTTP; a hostname makes Caddy fetch a certificate (`Caddyfile:2-4,9`; `docker-compose.yml:148`). The compose WUI build never sets tenant-host mode: `grep -c TENANT_HOSTS csi-spl-wui/src/docker/wui.Dockerfile docker-compose.yml` -> 0, 0, and `nuxt.config.ts:496` defaults `"0"`. One compose stack is one tenant on one host. No wildcard.

No domain, measured from the code (browser not driven, n = 0 on a live stack):

| shape | result | why |
|---|---|---|
| `http://localhost:8080` on the same machine | works | loopback is a secure context; `SPOOL_COOKIE_SECURE` defaults false (`docker-compose.yml:106`); `is_local` (`hub-entrypoint.sh:49-54`) |
| browser elsewhere via `ssh -L 8080:localhost:8080` | same reasoning; README does not say so | `grep -c 'ssh -L' README.md` -> 0 |
| `SPOOL_PUBLIC_URL=http://<ip>:8080` and `SPOOL_BIND=0.0.0.0` | sign-in can succeed; file upload and download call `crypto.subtle` | `spool-client.mjs:85-87` used at `:719`; `FileAttachment.vue:94,133`; `grep -rn isSecureContext csi-spl-wui/src \| wc -l` -> 0 |

P2 has no load balancer: `ls -d csi-spl-iac/src/terraform/031-gcp-hub-ingress` -> no directory. TLS is a Cloud Run managed certificate per mapped API host (032) and a Firebase Hosting certificate per WUI host (019, `cert_preference: GROUPED`). A wildcard left with the load balancer. Each extra tenant host is its own Firebase custom domain, DNS records and certificate wait.

The hosted WUI has tenant hosts on (`wui_tenant_hosts: true`, `dev.env.yaml:135`, `prd.env.yaml:138`), so a sign-in on the apex hops to `https://<tenant>.<fqdn>`. The hop probes `<host>/build.json` first and otherwise shows "your address is being prepared" (`tenant-host-boot.mjs:13-22,75-80`). Provisioning of that host is workflow 40. The file says revived on 2026-09-30 (`40_tenant-host-reconcile.yml:3-11`) and the cron is present (`:43`). GitHub says otherwise, this pass: `gh api repos/<org>/<repo>/actions/workflows/40_tenant-host-reconcile.yml` -> `state: disabled_manually`. Newest run in `gh run list --workflow 40_tenant-host-reconcile.yml --limit 5` is `2026-09-19T16:38:09Z` (cancelled). With the workflow off, a paid tenant stays on "being prepared" until an operator runs `do_spl_tenant_host_provision`.

A newcomer who only wants one tenant never needs that hop. Compose leaves it off. A fork that copies the env files turns it on.

Managed certificates are USD 0. One Cloud DNS zone is about USD 0.20/month on the vendor list page (unchecked this pass). The certificate wait is 10-30 minutes per new host (047, and the workflow 40 header).

## 2. Blockers

1. **Plain HTTP off localhost breaks files with a browser error.** `spool-client.mjs:86`, no `isSecureContext` check (1.2). A VPS with no domain is the shape a newcomer tries first.
2. **The zero-domain remote path is absent from the README.** `grep -c 'ssh -L' README.md` -> 0. The tunnel is what keeps `crypto.subtle` and the cookie.
3. **P1 backup is a paste** (1.1): unscheduled, on the same disk as the data, holding the root key, never run by CI.
4. **Workflow 40 is off while its header says revived** (1.2). Hosted sign-in for any tenant other than the apex waits forever. Both env files a fork would copy set `wui_tenant_hosts: true`.
5. **GCP has no no-domain mode, and two vendor default hosts would not be one.** The session cookie is `Domain` + `SameSite=Lax` (`internal/auth/handler.go:1406-1407`). `<site>.web.app` and `<svc>.run.app` are different sites, so the browser does not send that cookie on the WUI's API fetch. Compose works with no domain because Caddy is one origin (`Caddyfile:12-16`).
6. **The first cloud tenant prints its root private key on stdout**, then a second command invites the owner. On a cnf like dev, bootstrap-owner is `"true"` (`dev.env.yaml:295`) for the whole gap, so the first sign-in owns the tenant.
7. **Every cloud DB action refuses an env other than dev or prd.** `spl-cloud-cnf.func.sh:21`. Step 040 repeats it (`02-variables.tf:16`). Feeds 072 G9; the shell half is outside that row.
8. **Migration numbering is prose.** Hole at 0007, collision at 0021 (1.1). A new `0007_*.sql` is applied by `migrate.go:59-97` on databases that already have 0008..0112. No test checks the prefix.
9. **Backup retention is not in terraform** (`retained_backups` count 0, 1.1). A fork gets the platform default of the day it creates the instance. The "7" in the workflow 45 header does not move with a plan.
10. **lde runs the hub as a superuser** (1.1). Row level security does not bind. A contributor who only uses lde misses failures compose and cloud hit.

## 4. Questions for the owner

D15 already records "plain `http://<ip>` is not supported", and the spec parks workflow 40 with the orchestrator (F31; I re-measured `disabled_manually`, newest run `2026-09-19T16:38:09Z`). The open questions are the ones the merge did not ask.

1. **A41 as specified.** Recommended: **change it before L43 builds it** (NS4). An empty `BASE_DOMAIN` that only skips 005/025/032 leaves the WUI on `*.web.app` and the hub on `*.run.app`. The session cookie is `Domain` plus `SameSite=Lax` (`handler.go:1406-1407`), so the browser does not send it on that fetch. Compose is the no-domain product because Caddy is one origin. A GCP no-domain mode has to be one origin too.
2. **Fill prefix 0007, or rename the second 0021?** Recommended: **neither.** A rename breaks every applied sha. A late 0007 runs on databases that already passed that point. DB2 freezes both inside A45.
3. **Should lde use the owner/runtime split (DB7)?** Recommended: **yes**, inside A46. Same two logins as compose, so a contributor hits row level security on the stack they actually run.
