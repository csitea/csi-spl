Cost, from the Secret Manager pricing page read on 2026-10-04 (https://cloud.google.com/secret-manager/pricing): the first 6 active versions per billing account per month are free, then USD 0.06 per version per month; the first 10,000 accesses are free, then USD 0.03 per 10,000. A hub that versions only the DB DSN stays inside the free tier. This does not change the order below. Cloud Run injects the secret at revision start, so steady-state access is inside the free 10,000.

### 1.2 The installer on a fresh user (section 10)

`install.sh` is 476 lines. It refuses to run sudo (`install.sh:10`, and the three `sudo apt-get` lines at 154, 167 and 169 are text it prints). Base tools it names: bash 4, git, python3, tar, perl, flock, setsid, curl or wget. tmux missing is a warning (line 169). qwen also needs npm. Default CLI is `claude`, default env is `dev` (lines 81-82). `SPOOL_HUB_URL` has no default (line 132).

What a fresh user still has to bring:

1. The base packages, as root, if the image lacks them.
2. A clone. The script warns unless the parent directory name equals the repo name's prefix (`install.sh:156-162`). For `ENV=self`, the pin path does not use that parent: `do_spl_desk_cnf` reads `<org>-<app>` from the orc directory name (`spl-cloud-cnf.func.sh:136-139`).
3. Go, unless one new enough is already on PATH. `go.mod` says `go 1.25.14`. The installer downloads the latest from `https://go.dev` (`install.sh:272-284`). On 2026-10-04 that version string was `go1.27.1` and `curl -sI https://dl.google.com/go/go1.27.1.linux-amd64.tar.gz` returned `content-length: 70553950`. The built `spool` is linked into `<prefix>/bin`; the Go tree is not (`install.sh:305-313`). `use-go-toolchain.sh:14` looks under `/usr/local`, not under `<prefix>/share/spool-agent/tools`, so a later `do_spl_box_deploy` (spec 071 §5.1) does not see the Go this installer just fetched.
4. A tenant root key, or an admin who has one. Without `ROOT_KEY_JSON` the seat is PENDING and the script exits 0 (`install.sh:461-467`). 037 T005 is still open: `grep -n T005 csi-spl-doc/specs/037-spool-agent-install/tasks.md` -> line 32, `[ ]`.
5. A login at the chosen CLI vendor. The installer does not do that.

The seat failure is easy to miss. `do_spl_desk_pin` returns 3 when `spool hub-sync` fails, including when nothing answered (`spl-desk-pin.func.sh:105-112`), and it still prints a JSON line with `"pinned": false`. `install.sh:459-467` treats that JSON as success and does not look at the return code, so an unreachable hub is "seat PENDING", exit 0. In that function, `mode=self` means "the caller holds the root key" (line 64), which is a different word from `ENV=self`.

A dry run is not an honest preview of the fleet files. n = 1: `HOME=<empty temp> install.sh --dry-run --no-seat --cli none` exited 0, left no files under that home, and stderr contained `5 fleet fragment(s) rendered` and `fleet settings merged`. `y4-claude-config.py:31-32` returns before writing when dry is 1, then line 80 prints "rendered" anyway. On a real run the same step is on by default. `grep -c SPOOL_INSTALL_CLAUDE_CONFIG install.sh` -> 0; the switch lives only in `steps/y4-claude-config.sh:37`. The settings fragment sets `skipDangerousModePermissionPrompt` to true (`assets/claude/settings/00-fleet.json:2`). The standing orders include push-to-trunk (`assets/claude/claude-md/10-push-and-deploy.md:5`). Rendered skills get `SPOOL_ROOT` default `/var/spool-hub` and orchestrator `CLE-00` (`install.sh:393`). `spool-agent.sh:63` defaults the tenant to `t1`.

I did not repeat a full install on a clean image (n = 0 for wall-clock minutes). The dry run above returned in the same short call. The long pole of a real first run is the Go tarball plus `go mod download` (`go.sum` is 175 lines) plus one vendor installer. Disk and minutes for that full walk are in research 10; I am not restating them as my own measurement.

## 4. Questions for the owner

1. **Should a default `install.sh` write fleet standing orders and turn off Claude Code's dangerous-mode prompt?** Recommendation: **no.** R1. Our own boxes pass `--fleet`. This is the first thing a contributor's laptop hits (user story 1, step 3), and it does not need GCP.
2. **Should a new estate create the git-rel relay (step 020) at all?** Recommendation: **no, unless they ask.** The hub does not use that bucket. Skipping it removes the second key and the org-policy window for everyone who only wants a hub (R5). Keep the action for this estate (R6).
3. **May the seed-all action invent the session key, the wui key and the DB passwords, and stay quiet about SMTP, IdP and payment while those features are off?** Recommendation: **yes** (R8). The values go to a mode-0600 file passed as `--data-file`, never to the terminal.

## 5. Where I disagree

Both `research/09-secrets-keys-iam.md` (c-162) and `research/10-box-agent-install.md` (c-171) are on `origin/master`. I am not editing them. Spec `423dc1d0f` already folded most of their actions in (A30-A33, A49-A51). The points that should not be implemented as those files wrote them:

1. **09 §1.2 item 1 says gcp-002 lifts the key-creation ban "on the project only".** The policy document is `organizations/<GCP_ORG_ID>/policies/...` (`gcp-002-create-project-service-account.func.sh:119-122`). The project command is a reset (line 135), not an allow. The header comment describes the intent; the YAML is the org. Research 02 already says "at the org". K4 says to reuse that function for the relay key. Reusing it copies the org-wide window. R6 refuses that reuse. A20 is the shape to copy.
2. **09 does not list the leftover `roles/orgpolicy.policyAdmin` grant.** `grep -c remove-iam-policy-binding` on gcp-002 -> 0, against an `add-iam-policy-binding` at lines 128-130. The member is hard-coded as `user:`. A20 already requires the removal. A lane that implements 09's K4 without A20 will not remove it.
3. **09's identity table adds `billing.costsManager` to the project SA.** That grant runs only for `ENV=all` (`gcp-003-configure-proj-sa-permissions.func.sh:69-71`). dev and prd do not get it.
4. **09's cost line is "unchecked", and it treats 14 slot ids as 28 billed versions.** The pricing page (1.1) makes the first 6 versions free per billing account, and an empty slot with no version is free. (28 − 6) × USD 0.06 = USD 1.32 only when every slot has an enabled version all month. A minimum hub is inside the free tier. Their ranking (cost changes nothing) still holds.
5. **09 ranks the secret check, the seed-all and WIF-first ahead of the installer.** On `423dc1d0f` the owner's first story is a contributor with no GCP (spec §2.1), and §3.1 puts no-cloud self-host first. R1 and R2 block that story today. R5-R8 do not. I would not start a lane on A30 or A31 before R1 and R2.
6. **10's new action numbers A18-A25 collide with spec A18-A25** (keyless bootstrap, the preflight, the project-only key path, and so on). The lead already moved the installer items to A49-A51. A later lane should cite A49-A51, not 10's A18.
7. **10 is right that a dry run writes no files, and wrong that the dry run tells the truth.** My n = 1 dry run wrote nothing and still printed `rendered`. FR-003's "changes nothing" holds for bytes. It does not hold for the sentence a newcomer reads. R1 adds that check. I did not re-time their Debian-image walk, so I do not dispute their seconds or their disk figures.
8. **10's B5 ("the clone must sit at a fixed parent layout or the seat breaks") is stronger than the self-seat path.** The warning is real (`install.sh:156-162`) and matters for `./run` actions that take ORG from the parent directory. `ENV=self` pin resolution uses the orc directory name (`spl-cloud-cnf.func.sh:136-139`). A wrong parent warns; it is not what makes a self seat PENDING.
