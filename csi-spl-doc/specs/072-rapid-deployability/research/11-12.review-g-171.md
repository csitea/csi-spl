## 2. Blockers

1. **A hub-path push on a fork probes our hosts and can go green for it.**
   `20_hub-build-deploy.yml:705-714`: verify runs when test and
   prepare-deploy succeeded, including when deploy was skipped. The `if`
   does not mention `needs.deploy.result`. `22_deploy-verify.yml:12-16`
   says a skipped deploy still verifies. `verify-hub-endpoints.sh:92-96`
   passes on any non-empty `version`, `commit`, `built_at`. Our live hub
   answering 200 makes the fork's "Post-deploy smoke" **green**. A 5xx
   makes the fork **red** for a cause the fork cannot fix.
   `grep -c 'github.repository' .github/workflows/22_deploy-verify.yml` -> 0.
2. **wf 10 never returns a verdict on a fork.** Ten `runs-on` lines
   (1.2). The only escape in the file is the `sed` in the header (line 18).
   wf 11 does not run iac, orc, cnf or the hygiene sweep, so a red in
   those lands on trunk after merge. A push to a non-`master` branch of
   the fork runs neither 10 nor 11 (`push: branches: [master]` on both;
   11 also has `pull_request`).
3. **The only second-machine paragraph copies the root key.**
   `README.md:85-90`. `install.sh:461-467` already prints the one admin
   pin line when `ROOT_KEY_JSON` is unset. The paragraph also omits
   `--env self`, and the installer defaults that to `dev` (`install.sh:82`),
   which then has to match the hosted cnf hub (`spl-desk-pin.func.sh:31-33`).
4. **Skills on every fresh install address `CLE-00`.** `install.sh:393`.
   The rendered exit-clean and spawn commands message that id, not
   `--to orchestrator`. Two machines then each have a local `CLE-00` that
   is not the lease holder (current role id is `c-001`, spec 061).
5. **Same computed box id is taken silently.** `install.sh:128` falls
   back to the literal `host` when `hostname -s` fails, so two such
   machines both pin `box-<user>-host`. `do_spl_desk_up` on a shared box
   id is the 4409 eviction (058 H1, `ws.go:347`). The desk-pin default
   `box-desk` (`spl-desk-pin.func.sh:25`) is a second door, used when
   `DESK_BOX` is empty, which the installer does not do.
6. **A full second server still demands a GCP key.**
   `spl-box-deploy.func.sh:147-149`. That blocks crons and the lease loop
   on a compose hub (A17). It does not block blocker 3's laptop: the
   agent starts its own desk.

## 5. Where I disagree

### 5.1 With research 12 (c-172)

1. **wf 22 is not "not on a fork push".** Their table says 22 is "called
   by 20 only after a deploy, else dispatch". `20_hub-build-deploy.yml:711`
   runs it when prepare-deploy succeeded, and prepare-deploy succeeds with
   `any=false` (`:167-170`). Their blocker 3 therefore misses the one
   host probe that fires on a normal hub-path push, without anyone
   enabling a schedule. Their C2 list does include 22, so the action is
   right and the diagnosis is short. R2 adds the caller `if`.
2. **"60-67, 70, 85: green" on a fork push is too wide.** wf 60 does not
   run on push (`60_codeql.yml:12-15`). The others run only on their
   `paths`, except 64 (every push) and 15 (every push). A docs push does
   not run semgrep, gosec, checkov, hadolint, shellcheck, or actionlint.
3. **Agree** on the 10-vs-14 runner count, on wf 11 being a real public
   verdict, on the stale "self-hosted" header of wf 15 (line 2) and wf 85
   (line 2), and on "nobody has run this on a fork".

   `grep -ciE 'satellite|second machine|multi.?machine|fleet' README.md`

   `spool-agent.sh:264` seats the desk. Their M4 (ansible on any ssh host)
