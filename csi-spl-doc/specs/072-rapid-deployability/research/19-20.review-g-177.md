### 1.3 The job

Agree with 20's shape, with two changes in section 5: one long-lived project `<org>-<app>-cr`, emptied every run, **never** `projects delete`. Google's SQL page says delete the project; our delete action is not safe to call from CI (the table above), and the owner asked for one project (20 records msg `af863518`).

**Nightly (from empty, not from zero).** `workflow_dispatch` plus a nightly cron, `ubuntu-latest`, one run at a time, timeout 60 min. One run:

1. Render env `cr` from the template (20's CR3): run-unique SQL name, `deletion_protection: false`, `backup_enabled: false`, **`min_instances: 0`**, steps 046, 059, 060 and 120 off, no domain steps. Image tag is the sha. No `v*` tag is minted.
2. Apply the core steps 20 lists (state bucket, APIs, IAM, WIF, registry, SQL, buckets, Cloud Run, Firebase without a custom domain).
3. Bootstrap the schema, deploy hub and WUI, smoke health, `/version` equals the sha, and the wf 50 browser proof against the `run.app` and `web.app` URLs.
4. Always: destroy that run's resources, then delete anything still labelled for that run. Never the WIF pool, the state bucket, or the Firebase site. Never `do_gcp_project_delete`.
5. Hourly janitor: labelled resources older than 3 h, same refusal rules.

**Monthly (from zero).** Their option B, on a schedule, not instead of the nightly job: create a project, link billing, enable APIs, run the same smoke, delete **resources**, then delete **that** project only when its id matches a `cr-` prefix and the label. This is the stranger's first hour. It needs a folder and a creator role, which the nightly job does not.

**Time (core / nightly).** 20's 20-35 min estimate is the right band once the domain wait is weekly. Cloud SQL "a few minutes" (1.1 row 7) sits inside their unchecked 5-10 min. The certificate wait stays in their weekly full tier (plus 10-30 min; 047's 10-25 min for this product). I did not run it. n = 0.

## 2. Blockers

1. **Nothing publishes an image or a CLI binary** (1.1). Every fast path above pulls. A1 and A4 are still open. `git grep -l -i ghcr` on `.github/workflows` -> 0 files.
2. **The WUI URL is a build arg** (`wui.Dockerfile:30`). A published web image would still call localhost until A3.
3. **`ENV=cr` cannot be named** (`spl-cloud-cnf.func.sh:21`, `gcp-001-create-project.func.sh:44`, 14 terraform validations). The workflow cannot be written until a `cr` plan is legal.
4. **Nine `^csi-spl` name checks** (1.2). A rendered stranger cnf does not plan.
5. **Teardown defaults are the production defaults.** SQL `deletion_protection` true (`02-variables.tf:84`), Cloud Run `deletion_protection: true` (`all.env.yaml:59`), `cpu_idle = false` hardcoded (`04-cloud-run-service.tf:79`), `min_instances: 1` (`all.env.yaml:60`).
6. **`do_gcp_project_delete` is the wrong tool for CI** (`gcp-project-delete.func.sh:21,97,111`). Safe teardown has no action yet (20's CR1).
7. **P2 from zero has never been timed** (spec 072 G17). wf 50 proves P1 only, and it builds (`50_oss-standalone.yml:51`).

## 5. Where I disagree

`research/20-clean-room-ci.md` was absent when this view was formed and present on `origin/master` before this file was written (that path's tip `d5dd4e927`). `research/19-prior-art.md` was already there (c-167, `ae839a3d0`).

**19, row 1 and the upgrade mapping.** Discourse's `./launcher rebuild app` is the wrong model for A6. Section 2 ranks time first, and a rebuild is the cost Gitea does not pay (`docker compose pull` then `up -d`, 1.1 row 1). Copy Discourse's preflight, which 19's action 1 already extracts. Do not copy the rebuild.

**19, top 3 item 5.** "k3s pattern, checksum verified" blends two things. The command 19 quotes (`curl -sfL https://get.k3s.io` piped to `sh`) has no checksum argument. Zulip publishes `SHA256SUMS.txt` (1.1 row 2). Keep 19's done-criterion (a corrupted asset is refused). Drop the claim that the k3s one-liner is what checks it. k3s's node token is also the wrong lifetime; 19's action 6 (a short UI token) is the part to keep.

**19, blocker 4.** The odometer (`.version` 1.1.3, highest tag `v8.4.0`, one `stable-*` tag, this sha) does not change time, steps, or errors for a stranger. It can stay an open question. It is not one of the blockers in section 2. I did not re-measure how many tags remain before 9.9.9.

**20, the cost table and CR3.** Pricing the proof at `min_instances: 1` for the whole 30 minutes copies production (`all.env.yaml:60`) into a job whose smoke is a minute or two. With `cpu_idle = false` hardcoded, that choice is what makes an orphan about $60 / month. CR3 should set `min_instances: 0`. I did not re-time 20's n=20 medians (wf 50 median 173 s, wf 20 median 469 s, wf 30 median 143.5 s). Those stand.

**20, the words "from zero".** Option A keeps the project, the APIs, the WIF pool, the state bucket and the Firebase site. That proves the steps still apply. It does not prove a stranger's first hour (project create, billing link, API enablement), which gcp-001 refuses for any env but dev, prd, bkp and all (`gcp-001-create-project.func.sh:44`). Call the nightly job "from empty". Keep option B as a monthly run. I agree the nightly job must not call `projects delete`: I started from Google's "delete the project" sentence and dropped it after reading `gcp-project-delete.func.sh:21,97,111`.
