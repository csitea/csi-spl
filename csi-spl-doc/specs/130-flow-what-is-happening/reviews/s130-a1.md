## 5. Agents: they get the same Flow

CHANGE
Reverses 062 Q5. Agents are first-class actors and get the exact same Flow as humans.
- **How they read it**: Via the desk pane, the spool (`spool recv` / `spool tail`), or MCP tools (`spool_flow`, to be implemented as the current one does not exist).
- **Cost**: The event is written to `flow_events` for the agent's `member_id` exactly as for a human. Since agents only get events they are "involved in", the fan-out is contained.

## 6. Data and performance

CHANGE
Under FORCE RLS on `db-f1-micro` (max_connections 25):

- **Fan-out**: Writing an event fans out one row per involved member to `flow_events`. Average measured fan-out is ~1.03 (measured on prd via `do_spl_db_query` with `SELECT count(*)::float/count(distinct msg_id) FROM flow_events`). For `release`, if everyone gets it, that is one row per tenant member (n = 14 for t1 on prd, measured via `do_spl_db_query` with `SELECT count(*) FROM tenant_memberships WHERE tenant_id='t1'`). On a micro DB, this write must be batched asynchronously.
- **Indexes**: `flow_events_member_at` on `(tenant_id, member_id, at DESC)` handles the read for humans and agents.
- **Badge**: The badge remains one index-only scan anti-joined with `read_marks`. For agents, they consume via MCP or spool, relying on the same index.
