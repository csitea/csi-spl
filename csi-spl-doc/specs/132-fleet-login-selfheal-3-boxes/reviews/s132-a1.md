# Review of Spec 132 (s132-a1)

**CHANGE** (Gap 1: Numbers and proof command)
- **Reason**: The spec lacks outage times, renewal intervals, quantifiable 48h proof pass/fail criteria, and a named proof command.
- **Numbers**:
  - Outage times: unmeasured (from facts: ~17:45Z, 18:16-18:22Z, 18:31Z).
  - Renewal interval: unmeasured.
  - 48h proof criteria: unmeasured (spec.md:19 "successfully renew their tokens for 48 hours" is not a measurable criterion).
  - Proof command: unmeasured.

**CHANGE** (Gap 2: Refresher-down / peer-unreachable)
- **Reason**: spec.md:20 ("the peers will eventually expire ... Unreachable peer: the push fails, and the peer expires") is not a design. Needs detection, alert, and who acts.

**CHANGE** (Gap 3: Credential file path)
- **Reason**: spec.md:15 contains `~/.claude/credentials.json`. Public repos must not contain credential paths.

**CHANGE** (Gap 4: 3rd cloud box)
- **Reason**: The spec does not detail the first login process for the 3rd cloud box or how it joins the self-heal (same installer).

**CHANGE** (Gap 5: Hourly rotation)
- **Reason**: Missing cross-reference that the hourly rotation for every agent (owner order 2376e019 / 4172ee7b, lane queued) must probe the login before rotating.

**CHANGE** (Gap 6: Independent tokens assumption)
- **Reason**: The spec must explicitly state that separate `/login` on the same account yielding independent tokens is an assumption, and make the proof decide.

**CHANGE** (Additional: Restore process)
- **Reason**: spec.md:35 and spec.md:36 must specify that any restore must be once per stuck seat with a re-check before each stop. A previous restore pass (18:31Z) restarted 8 agents for nothing because it lacked a re-check.

**CHANGE** (Owner Addendum: All agent kinds)
- **Reason**: The spec only covers Claude. It must cover ALL agent kinds (claude, grok, mistral, agy, qwen). Specifically, it must detail each vendor's login, its renewal, and how a dead login is detected and repaired per box.
