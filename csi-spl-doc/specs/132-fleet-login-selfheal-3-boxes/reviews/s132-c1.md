  `git grep -c do_spl_agent_login_proof -- ':!csi-spl-doc'` -> 0 hits: it does

  exist: `do_spl_agent_login_check` already logs per tick, per box,
  `probe=<verdict> stuck_login=<n> ... copied=<n>`

  measured: the delta between successive `expiresAt` values when the sha

- spec.md:22 "0 agent drops" is not checkable. Proposed pass, all of:
  (a) 48 h wall clock with both boxes on their own login and
  `SPOOL_LOGIN_PEERS` empty on both; (b) at least 2 renewals seen per box
  (sha prefix change with a later `expiresAt`), so the window really covered
  a refresh; (c) 0 ticks with `probe=expired` on either box; (d) 0 ticks with
  `stuck_login` > 0. Fail: any (c) or (d), and say whether it fell within
  10 min of the OTHER box's renewal. Report n = renewals per box; with n = 2
  it is evidence, never proof.

### 1.2 Gap 2, refresher down / peer unreachable: CHANGE

spec.md:25 still reads "peers eventually expire" plus "the watchdog alerts".
The code already does more than the spec says, and less than it needs:

- Peer unreachable: built, cite it. `_lc_peer_one` warns
  "peer <tag>: no credential to compare (... unreachable)"
  (`spl-agent-login-check.func.sh:207`), and the alert goes to the dispatch
  lease holder, deduplicated by state (header lines 31-33).
- Refresher down: NOT detected. A peer never checks that its refresher is
  alive; it notices only when its own probe says `expired`, i.e. after the
  outage began (then the repair refuses to restore into a dead login and
  alerts, `spl-agent-login-check.func.sh:223-228`). Needed: each peer's tick
  warns when its own `expiresAt` is less than one renewal interval away and
  the sha has not changed in that interval ("refresher silent"), so a human
  gets the alert before the expiry, not after.
- Who acts: say it. The dispatch lease holder posts it to the owner as a
  blocker; the owner runs `/login` on the refresher box (no agent can, owner
  a7499dc2). State the expected time to a human.
