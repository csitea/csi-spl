## 1. The Problem and What Exists Today (Measured on `origin/master` `268fbad65`)

Before Spec 197, global search (`/s`, `/search`) outputs grouped hits into `ChannelSidebar.vue`'s narrow left panel (`SearchSidePanel.vue` inside the 25–30% sidebar) and navigates to `/search?q=...` (`pages/search.vue`), while calendar search (`CalendarPhoneSearch.vue`) is a separate modal dialog over `/calendar`. Neither gives a user a wider, dedicated slide-open list-left / preview-right workspace triggered straight from `/s` / `/search` in the Omnibox where they can scan results across every linkable object (starting with real calendar entries nearest-upcoming first), cycle through hits with `ArrowUp`/`ArrowDown` or click while previewing each live and alone on the right without leaving search, actually open a hit (closing search and restoring the section's left pane), share a results link, or multi-select hits for bulk actions such as Multicast prompt.

### 3.4 Row Anatomy, Sorting, Filtering, and Paging (`FR-US-07` – `FR-US-10`)

- **FR-US-07 (Row anatomy).** Every hit renders in one flat list inside the wider (`48%` default) left results pane. Left to right on desktop (compact row; two lines on phone with 44 px touch targets: line 1 = kind + title, line 2 = where + who + when):
  1. **Selection tick box** (added in Wave 2 row **W3**; always visible on desktop, shown after long press on phone). Focus stays on the row (roving `tabindex`): clicking the row previews on the right and `x` ticks; clicking the tick box itself ticks without changing preview (`aria-checked`); a `Tab` landing on the tick box makes `Space` tick, as everywhere else.
  2. **Kind badge:** `UiIcon` + localised kind word (`Calendar`, `Topic`, `Card`, `Message`, `Issue`, `Lane`, `Event`, `File`, `Doc`, `Note`, `Contact`, `Channel`, `Person`, `Agent`, `Box`, `File line`).
  3. **Title & match highlight:** entry title + start date/time for calendar, topic title, `KEY + title` for issues, agent/scope summary for lane, first line / snippet for messages & cards — with match ranges wrapped in `<mark>` as escaped **text nodes** (never server HTML, `search-v1.md` §4).

  5. **Who** last modified/authored it (display name / agent id, omitted where a kind has no actor).
  6. **When:** start date/time for `type:calendar` (`starts_at` in the reader's time zone, relative hint when today/upcoming); relative `updated_at` (e.g. `12m ago`, `3d ago`) with exact timestamp on hover (`how-to-post.md` §4) for mixed-kind results.

### 3.8 Shareable Links and Rights (`FR-US-18`)

- **FR-US-18 (Shareable `/search?q=...` link without a separate results page & access control — HC3 + Q1 = `LIV` confirmed `msg:9383a7be`).**

### 3.9 Loading, Zero-Hit, Partial, and Error States (`FR-US-19`)

- **Loading:** Announces `Searching...` (`aria-live="polite"`) in the left results pane; while refining an existing query, prior rows stay dimmed until replaced.
- **Zero hits:** Shows `Nothing found for "<query>"` plus up to three actionable tips (try shorter words, clear a `type:` or date filter, check spelling), and an empty hint in the right preview pane.
- **Bad query (`400 bad_query`):** Displays the hub's error detail and highlights the offending token at its UTF-16 offset (`search-v1.md` §5.1) above the list.
- **Rate limit / Timeout / Offline (`429` with `Retry-After` seconds, `503 search_budget` 7 s, network failure):** Displays one plain sentence and a **Retry** button (`LazySearchErrorNotice` pattern); status/token/reference appear only when the Debug pane is enabled.
- **Partial source failure:** If one backend source times out or fails while others succeed, renders the hits that arrived plus a non-blocking notice naming the source that could not be searched with a **Retry** action. A source omitted by role, feature kill-switch, or access gating (e.g., `lane` for non-staff) is never a partial failure; notices fire only on real timeouts or errors for sources the caller is authorised to search.
- **Warnings and notices:** Displayed above the list (unknown operators searched as text; `file_streams_staff_only`, `events_capped_500`, `relevance_pool_capped`, etc.).
